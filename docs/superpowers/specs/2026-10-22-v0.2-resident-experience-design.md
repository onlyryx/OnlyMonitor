# Only Monitor v0.2.0 Alpha：日常常驻体验

日期：2026-10-22。状态：v0.2 功能、自动检查及本机发布验证已完成；未验证场景与实际结论见 `docs/v0.2-verification.md`。

## 目标与成功标准

用户已选择 v0.2 优先改善日常常驻体验。本版让 Only Monitor 在隐藏窗口后继续可靠采集，通过托盘恢复窗口，并保存少量明确有用的设置；补充内存与网络趋势。

保留 Tauri 2、React、TypeScript、Vite、Tailwind CSS、Recharts、Framer Motion 和 sysinfo，延续现有视觉风格。继续普通用户权限运行，不上传监控数据、不运行 Shell、不发起 AI 请求、不部署网站或修改 DNS。

成功标准：

1. 同一用户会话中重复启动只恢复已有应用，不产生第二个采集循环或托盘图标。
2. 隐藏主窗口两分钟后恢复，仍能看到最近一分钟真实历史；隐藏期间前端不维持采集轮询。
3. 托盘显示／隐藏／退出行为清楚；退出后应用进程和托盘项消失。
4. 修改采样间隔或关闭窗口行为后，运行时生效；保存成功的配置在重启后恢复。
5. CPU、内存及所选网络接口的趋势均使用真实时间和采样值；初始、错误、休眠间隔不填充伪造值。
6. 完成自动化回归、实机常驻检查、Release 构建，以及隔离测试目录中的安装／卸载／覆盖升级验证；不能实际验证的项目明确保留为限制。

## 当前代码依据

- `src/useMonitor.ts` 的前端定时器发起采样，历史仅在 React 状态中。隐藏 WebView 后，这个结构不适合作为后台采集的保障。
- `src-tauri/src/lib.rs` 的 `get_snapshot` 每次调用触发 `Collector::sample()`；互斥和一秒缓存防止并发采集，但没有独立后台调度。
- `collector.rs` 已具备 CPU 初始化、网络计数差、磁盘定期刷新、卷去重，继续复用。
- Settings 当前只读，托盘与单实例功能尚未启用。
- 目录尚未初始化 Git，现有 v0.1 的源码、验证记录和安装包需要在实施前保存可恢复基线；此设计阶段不初始化仓库或覆盖发布产物。

## 方案比较与选择

| 方案 | 优点 | 代价／问题 |
| --- | --- | --- |
| 保持前端驱动，仅增加托盘 | 代码改动少 | 隐藏窗口仍依赖 WebView 定时器，历史随前端生命周期变化，不满足常驻目标 |
| 单个 Rust 后台采集器 + 前端读取缓存 | 隐藏后继续采集；历史与 UI 解耦；沿用现有 Collector | 需要调整 command、历史归属与退出生命周期 |
| 独立 Windows 服务／辅助进程 | 可脱离应用窗口进程运行 | 本版没有跨登录会话常驻需求，增加部署与权限复杂度 |

选择第二种。只新增本版需要的运行时与配置边界，不建立通用任务调度框架。

## 范围与默认行为

### 后台采集

- 应用成功初始化后启动唯一 Rust worker。Collector 由该 worker 独占，UI 请求只读取结果，不触发系统刷新。
- 默认间隔 1 秒，支持 1／2／5 秒三个选项。上一轮完成后等待指定间隔，不重叠、不排队补采；实际间隔包含采集开销。
- 磁盘继续每 30 秒刷新，独立于 CPU／内存／网络采样间隔。
- 保留最后一次成功快照、最近采集错误和采集尝试时间；失败不把旧值重新标成新样本。
- 历史由 Rust 持有，限制为最近 60 秒内最多 60 条采样结果。失败条目的指标为空，以便图表断线；不保存到磁盘。2／5 秒间隔时自然少于 60 个点。
- 采集不持有供 UI 读取的状态锁执行慢系统查询，避免磁盘查询阻塞窗口恢复与状态读取。
- 修改间隔只唤醒／调整现有 worker，不启动新循环。退出时唤醒等待中的 worker 并停止后续采集。
- sysinfo 的在途底层系统调用不能承诺立即取消；界面超时状态与应用退出路径不能依赖无限等待该调用完成。

### 托盘与窗口

- 首次启动显示主窗口；提供应用图标及显示窗口、隐藏窗口、退出菜单。
- 左键单击托盘恢复并聚焦窗口；右键打开菜单；不依赖双击才能恢复。
- **建议默认：关闭窗口隐藏到托盘**。Settings 提供“隐藏到托盘／退出程序”选项。原生最小化仍保留常规任务栏行为。
- 在 Overview 与 Settings 用简短文案说明关闭后仍在运行、可从托盘退出，不增加阻断式确认弹窗。
- 托盘创建失败时禁止进入无法恢复的隐藏状态：关闭按钮按退出处理，界面显示托盘不可用说明。
- 托盘退出无条件真正退出，不受关闭窗口设置影响。操作失败展示可见错误；隐藏失败不伪装成功。
- 重复启动通过官方 single-instance 插件恢复已有窗口，不接受或执行命令行传入的任意命令。
- 本版不增加开机启动、Windows 服务、通知气泡或动态托盘图标。

### 设置保存

只保存三个用户偏好：

| 字段 | 默认值 | 校验与行为 |
| --- | --- | --- |
| `samplingIntervalSecs` | 1 | 仅允许 1、2、5；在 Rust 边界再次校验 |
| `closeBehavior` | `hideToTray` | 仅允许 `hideToTray`、`exit` |
| `selectedNetworkInterface` | 空，表示所有接口 | 字符串或空；接口缺失时保留选择并提示不可用，不静默展示其他接口数据 |

配置文件含格式版本 `schemaVersion: 1`，存于 Tauri 提供的应用配置目录。由 Rust 通过固定路径读取／写入，不给前端通用文件访问能力，也不接收前端指定的任意文件路径。

用户修改后明确保存；保存成功才更新生效值并显示成功状态。保存失败保留原有效设置，展示错误，不把未持久化的值写成已保存。

新安装无配置时使用默认值；损坏、无法读取或不支持的格式版本使用默认值并提示原因，不自动覆盖原文件。显式保存时写入经校验的配置，用同目录临时文件加替换方式降低写入中断风险。这里只持久化偏好，不保存系统指标、历史或主机信息。

主题继续固定深色；不增加窗口位置记忆、主题系统或未实现开关。

### 历史与网络选择

- Overview 保留 CPU 曲线，内存卡片补充最近 60 秒使用率趋势。
- Network 增加接口选择，以及同一时间轴的上传／下载速率曲线。保留现有累计字节与接口明细。
- “所有接口”继续注明可能重复计数，不把合计称为互联网出口带宽。
- 选择接口不会重置采集器；从已有有界历史中取该接口数据。接口未出现、计数器重置或首轮采样显示空值，曲线不跨缺失段连线。
- 恢复窗口先读取完整缓存历史；可见期间串行拉取状态，隐藏时停止拉取并停止仅用于 UI 的时钟。恢复时立即同步，无需补发隐藏期间的请求。
- 页面切换、React StrictMode 重挂载、重复打开窗口都不得创建额外后台采集任务。

## 状态、休眠与时钟

- 初始化时 CPU／网络仍等待有效基线，沿用 v0.1 的真实数据规则。
- 数据过期阈值随间隔变化，采用 `max(3.5 秒, 3 × 配置间隔)`；避免 5 秒采样时每轮误报过期。
- 后台观测到采样间隔大于 `max(10 秒, 3 × 配置间隔)` 时按采样中断处理：重新建立 CPU／网络基线，不显示跨休眠的平均速率；历史保留真实缺口。
- 不主动唤醒电脑。系统休眠期间不承诺采集，恢复后继续工作。
- 墙上时钟大幅回退／跳变时清理不再一致的时间轴并重新初始化差分指标；速率计算仍使用单调时钟。
- 采集错误、配置错误与托盘错误分开展示。采集恢复可以清除旧采集错误，不掩盖仍存在的配置／托盘问题。

## 代码与接口边界

- `collector.rs`：只执行一次真实采样及差分计算，增加重置基线能力；保留磁盘缓存和去重规则。原来为前端重复请求设计的缓存逻辑需要随职责转移调整，不能与可配置调度重复控制节奏。
- 新增聚焦的 Rust 运行时模块：唯一采集 worker、状态缓存、有界历史与停止通知。
- 新增配置模块：配置 DTO、校验、固定目录读写、可见错误。
- `lib.rs`：注册共享状态、只读监控 command、设置读取／保存 command，接入托盘和单实例生命周期。
- `model.rs`：扩充运行状态、历史和设置数据结构；继续用 ts-rs 生成 TypeScript 类型，并执行一致性测试。
- `api.ts`／`useMonitor.ts`：改为读取后台状态，处理可见性和串行拉取，不再充当采集调度器或历史真源。
- `App.tsx` 与样式：只修改托盘提示、真实设置与新曲线所需部分；必要时提取被多个图表实际复用的组件，不做无关重构。

依赖策略：沿用已验证版本，启用 Tauri 内置 `tray-icon` 能力；采用官方 single-instance 插件。配置读写使用 Rust 标准库与 serde_json，不引入数据库、通用文件插件、Shell 插件或额外状态管理框架。安装前核对插件与现有 Tauri／Rust 兼容性，并锁定依赖。

官方依据：[系统托盘](https://v2.tauri.app/zh-cn/learn/system-tray/)、[Single Instance](https://v2.tauri.app/plugin/single-instance/)。

## 验收与验证

| 项目 | 验证方式 |
| --- | --- |
| 唯一采集循环 | 自动化验证多次读取不触发新采样；改设置不增加 worker；重复启动实机验证 |
| 后台历史 | 隐藏两分钟，恢复检查最新时间与最近一分钟历史，确认隐藏期间无前端轮询 |
| 有界历史 | 覆盖 1／2／5 秒间隔、长时间采样、失败与恢复，始终不超过时间／数量上限 |
| 配置 | 正常保存重启、非法值、损坏文件、不可写目录和不支持格式版本；失败不显示成功 |
| 差分初始化 | 首轮、接口消失／重现、计数回退、长间隔与时钟跳变 |
| 退出 | 分别从托盘与配置为退出的关闭按钮退出，检查进程与托盘项清理 |
| UI | 导航、键盘操作、窄窗口、不同采样间隔的状态阈值、接口不可用提示 |
| 常驻开销 | Release 可见／隐藏各运行至少 10 分钟，记录应用自身 CPU 与内存趋势；短时观测不作为无泄漏证明 |
| 发布 | 前后端测试、类型检查、格式、Clippy、Release 与 NSIS 构建；隔离目录验证安装／卸载／v0.1 到 v0.2 覆盖升级 |

普通账户、多设备、真实休眠恢复、Explorer 重启后的托盘恢复等实机项目，只有实际执行并留存结果后才写为通过；不能用自动化逻辑测试代替实机验证结论。不修改用户现有卷挂载或网络配置来制造测试场景。

## 不在本版范围

温度、GPU、Ping、磁盘 I/O 与 S.M.A.R.T.、Ollama 模型或分析、主题切换、开机启动、长期历史存储、自动更新、网站／DNS 及代码签名。保留已有 Coming Soon 和扩展接口，不扩大权限。
