# Only Monitor：快速了解与负载来源设计

日期：2026-10-27。目标阶段：v0.5 Alpha 候选。

## 意图

帮助用户快速查看本机状态，在系统负载偏高时得到克制的提示，并从总体 CPU／内存读数继续找到主要占用来源。用户选择了进程占用列表，并补充 Only Monitor 不应成为“大号任务管理器”；随后确认托盘摘要和高负载提醒也一并纳入。

## 方向与范围

已选定一个“快速了解与定位负载”主题，包含三项：

1. 资源来源页：解释当前主要进程占用，提供诊断线索。
2. 托盘实时摘要：不打开窗口即可看到 CPU／RAM 当前值和采集状态。
3. 本地高负载提醒：持续高负载时用 Windows 原生通知提醒；需要用户在设置中主动启用。

这些是同一条使用流程：快速查看 → 发现异常 → 判断主要来源。托盘摘要和提醒不是独立的多主题发布项。

## 目标

- 新增 `Activity` 页面，分别按 CPU 与驻留内存排序展示当前前 8 个进程；每行显示进程名、PID、CPU 使用率和驻留内存。
- 从 Overview 的 CPU 卡片提供“查看负载来源”入口；侧栏也可直接进入。
- 托盘提示每轮成功采样后更新 CPU、RAM；初始化和采集失败显示清晰状态，不将旧值伪装成新值。
- 高负载提醒默认关闭。启用后，CPU 或内存达到 90% 且持续 30 秒发送一条本地通知；该指标在同一高负载周期不重复通知，低于 80% 连续 60 秒后重新待命。
- 继续使用唯一 Rust 采集 worker 和现有采样间隔；不另起采样循环。
- 首轮、新出现进程或采样间断时，进程 CPU 使用率等待基线，不伪装成 0%。
- 当前进程快照只留在内存，不进入已有 60 秒历史，不落盘、不上传；不要求管理员权限。

## 明确不做

- 不提供结束／启动进程、进程优先级、进程树、服务、启动项、命令行、可执行文件路径或完整进程表。
- 不加入进程搜索、筛选、长期历史、告警阈值配置、重复通知冷却配置或 AI 分析。
- 不对外发送监控数据，不新增任意 Shell、HTTP 或系统权限能力。

## 页面与交互

- Activity 页面标题为“负载来源”，说明“查看当前主要资源占用；Only Monitor 不管理进程”。使用 v0.4 已选定的浅色视觉系统，不另做主题。
- 提供“CPU”与“内存”两个排序视图，每个视图最多 8 项；每行同时展示两类资源读数。切换只改变排序依据。
- 尚未建立 CPU 基线的进程置后并标注“等待采样”；全体均未就绪时显示明确的初始化提示。
- 显示真实采样时间和受保护进程可能不可见的说明。
- Settings 增加“持续高负载时通知我”开关，默认关闭；保存失败保持原设置并给出反馈。
- 托盘摘要仅显示短文本，例如 `CPU 24% · RAM 38%`；初始化与错误态使用简短状态词。

## 数据与架构

- 复用锁定版本的 sysinfo `System` 实例；进程刷新只读取 CPU 和 resident-set memory，不读取命令行、路径、磁盘 I/O 或 tasks。
- sysinfo 进程 CPU 值可能超过 100%（多核累加）；除以逻辑处理器数后显示为整机容量百分比。进程占用之和不保证与系统总 CPU 使用率逐点相等。
- 内存标为“驻留内存”，不称为专属物理内存；共享映射会令进程驻留内存之和与系统内存不同。
- 以 PID 与启动时间作为内部进程身份，避免 PID 重用沿用旧 CPU 基线；身份字段不暴露给 UI。
- CPU 基线复用现有休眠／时钟跳变中断判定，两个有效进程样本之后才显示 CPU 值。
- 进程快照放在 `MonitorState` 当前状态，不加入 `Snapshot` 或历史，避免每秒历史复制进程列表。Rust DTO 经现有 `ts-rs` 契约生成 TypeScript 类型。
- 一次 worker 采样完成后，用同一结果更新 MonitorState、托盘摘要和高负载判定；通知失败不能中断系统采样。
- sysinfo 可能略过 Windows 保护进程；不提权、不猜测缺失行，并明确说明该限制。

## 提醒边界

- 使用 Tauri 官方 notification 插件的 Rust API 发送桌面通知；不在前端隐藏轮询中实现提醒。
- 只有用户开启设置后才评估通知；失败或缺失的样本不计入连续高负载时长。
- CPU 与内存分别维护触发／复位状态；一个指标低于 80% 连续 60 秒后该指标重新待命。
- Windows 原生 toast 需通过已安装应用验收；开发态通知的应用名称／图标可能不同。

## 隐私、性能与验收

- 进程名、PID、CPU 和驻留内存只在当前会话使用；不保存到设置、历史文件、日志或网络请求。唯一持久化新增值为用户主动选择的提醒开关。
- 每种排名最多 8 项；过程数据不进入 60 秒系统历史。进程刷新复用现有 worker，每轮一次。
- 自动检查覆盖：进程首次采样、次采样就绪、PID 重用、采样中断、CPU／内存排名上限；进程快照与系统历史隔离；高负载 30 秒触发、低于 80% 60 秒复位、错误样本打断计时、同一周期不重复通知；设置默认关闭和 schema 迁移；托盘文案的初始化／失败／有效数据格式；前后端 DTO 一致。
- 原生 Release 检查真实进程数据、普通权限可用、托盘采样更新、通知默认关闭和显式启用、安装后 Windows toast、窗口隐藏时提醒仍工作、窄窗口布局，以及无进程控制操作。
- Release 下测量增加进程采集前后的单轮耗时与返回进程数量；没有真实测量时不宣称额外成本可忽略。
- 全部必做项通过后才将版本更新到 0.5.0 Alpha 并生成安装包；失败项按验收记录如实保留。

## 实施判断

- sysinfo 当前锁定为 0.37.2；此版本的进程 CPU 值可能超过 100%，进程 `memory()` 是 resident set。实现需保留以上明确口径。
- 若 sysinfo 无法识别特定受保护进程，页面说明采集限制，不显示臆造的逐进程错误。
- Rust 返回 CPU 排名和内存排名各最多 8 项，避免把完整进程表传给前端。
- Windows 通知采用官方 Tauri 插件；仅 Release 安装包用于通知通过性判断。
