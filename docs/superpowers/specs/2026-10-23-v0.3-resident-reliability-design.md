# Only Monitor v0.3.0 Alpha：常驻可靠性

日期：2026-10-23。状态：用户已确认设计并授权计划后连续实施；v0.3 实施、最终 Release 验证和一小时显示／隐藏常驻观察均已完成。实际结论与未覆盖范围以 docs/v0.3-verification.md 为准。

## 意图与现状

用户选择继续优先完善常驻可靠性，并确认官方 autostart 插件接入、手动启动显示窗口、登录启动可选隐藏的方案。

v0.2 已有唯一 Rust 采集 worker、有界 60 秒历史、原生托盘、单实例恢复和设置保存。前端仅在可见时轮询；配置保存使用固定路径及原子替换。当前主窗口默认可见，启动过程尚不区分登录启动与手动启动。v0.2 实测显示及隐藏各约 10 分钟，休眠恢复、Explorer 重启、独立受限账户和托盘菜单实际点击未验证。

本版目标是在沿用架构的前提下，完善启动控制、恢复和退出，依据实测处理资源问题，不新增监控指标。

## 方案比较

1. **官方 Tauri autostart 插件（用户已选）**：由 Rust 调用启用、禁用和查询；插件接收固定登录启动参数。少维护平台代码，代价是新增一个需锁定兼容版本的依赖，并验证系统状态、卸载清理和路径变化。
2. **自行维护 Windows 启动注册表项**：可控制全部细节，但要自行维护引用、路径、错误处理及系统兼容。本版不采用。

官方说明：https://v2.tauri.app/plugin/autostart/ 。实施前以锁文件、插件源码及当前工具链确认兼容版本，不运行会覆盖项目配置的初始化命令。

## 范围与明确不做的事项

- 保留现有 Tauri 2、React、TypeScript、Vite、Tailwind、Recharts、Framer Motion、sysinfo 与视觉风格。
- Settings 增加登录启动控制和登录启动隐藏偏好；保留 1／2／5 秒采样、关闭行为、网络接口选择。
- 验证恢复、失败回退、单实例、退出、配置迁移和安装卸载；可复现问题先补回归测试再修复。
- 不增加温度、GPU、Ping、磁盘性能、AI、长期指标存储、自动更新、系统服务、守护进程或自动重启机制。
- 不部署网站、不修改 DNS、不上传指标、不执行任意 Shell、不要求管理员权限。
- 不主动升级无关依赖或重构正常工作的采集模块。

## 启动与窗口行为

| 场景 | 行为 |
| --- | --- |
| 首次安装／普通手动启动 | 显示主窗口；不自动注册登录启动 |
| 登录启动，隐藏偏好开启且托盘可用 | 主窗口不闪现，后台开始采集，托盘可恢复 |
| 登录启动，隐藏偏好关闭 | 显示主窗口 |
| 登录启动但托盘初始化失败 | 显示主窗口并报告失败，关闭窗口可真正退出 |
| 已运行时再次手动打开 | 恢复已有窗口，不创建第二个 worker |
| 已运行时收到带登录标记的第二实例 | 同样恢复已有窗口；第二实例不得隐藏正在使用的窗口 |
| 托盘退出或关闭行为为退出 | 真正退出，不因启用登录启动而自行重启 |

实现决策（本次工程选择）：使用固定 `--autostart` 参数区分登录入口；只影响首次进程的初始窗口选择。此标记不是权限凭据。初始化先创建隐藏主窗口、装配服务和托盘，然后根据入口及偏好显示或保持隐藏，并发布真实可见性；不通过先显示再隐藏实现。手动入口不受隐藏偏好影响。

本地隐藏偏好默认 true，即用户以后开启登录启动时默认安静常驻；开机启动自身默认不启用。新增 UI 文案明确指 Windows 用户登录后启动，而非 Windows 服务。

## 启动项真实状态与保存

实现决策：**系统启动项注册状态独立于本地偏好保存**，避免普通配置文件与系统注册两份真值产生无法保证的跨资源原子事务。

- 本地 Settings 只新增 `hideOnAutostart: boolean`，不保存一个自动生效的 `autostartEnabled` 字段。
- Settings 内单独一行“登录 Windows 时启动”，显示系统注册状态、查询失败或更新中。操作为显式启用／关闭，旁边说明立即生效，与下方“保存设置”区分。
- 进入 Settings、恢复该页面和用户点击“刷新启动状态”时查询；不在每秒采样或状态轮询里访问注册表。
- 查询结果是“启动项已注册／未注册／无法读取”，不声称能保证下次登录一定执行。Windows 启动应用禁用状态或策略限制可能不在插件查询覆盖范围，应明确说明；不绕过系统设置。
- Rust 提供类型化的查询及切换 commands，路径、名称和参数均由后端固定，前端仅传布尔值；沿用 ts-rs 契约。不安装仅为前端直接调用插件所需的 JS 依赖，不开放通用系统访问权限。
- 切换操作后重新读取实际注册状态；失败显示操作错误与可读到的实际状态，不能虚报成功。查询失败显示未知，不能当作关闭。
- 启动项操作和普通设置保存共用前端互斥状态，避免重复提交；后端串行处理启动项变更。普通采集继续，不持有采集状态锁进行系统操作。
- 应用启动时不根据配置偷偷启用或修复启动项；被用户或系统禁用后不自动重新注册。开启只发生在用户明确操作时。
- 隐藏偏好保存遵循现有保存成功后才应用的原则；切换登录启动不会提交尚未保存的其他表单值。

## 配置兼容

实现决策：配置 schemaVersion 升至 2，其他字段沿用；从 v0.2 的 schemaVersion=1 读取时保留原有采样间隔、关闭行为和接口选择，新增隐藏偏好采用 true。加载迁移只在内存中进行，显式保存时才写入新格式，不因启动改写原文件。

配置缺失时使用默认值且不报错；损坏、非法或未来版本配置使用默认值并显示明确错误，原文件保持不变。失败不会注册启动项。降级 v0.2 无法识别 schema 2，将默认运行并提示错误；交付中说明，保留 v0.2 源码、二进制和迁移前配置备份，不能声称降级自动兼容。

## 恢复与错误处理

- 沿用唯一 worker 和单调时间差分，不因显示／隐藏、恢复或设置页面挂载启动新采集器。
- 休眠期间不采集、不唤醒电脑；唤醒后的长间隔重新建立 CPU／网络基线，初始化用空值表示；曲线保留真实空档，不伪造连续数据。
- 所选网络接口消失时保留选择、显示不可用；恢复后重新建立必要的差分基线。不得通过实机测试断开用户当前远程工作所依赖的接口。
- 恢复窗口立即读取缓存，轮询恢复且不重叠；失败状态可见，不能出现窗口已显示而 UI 永久停更。
- 验证 Explorer 重启后托盘恢复能力，先核对现有 Tauri／托盘依赖是否已有处理，避免重复重建托盘。未实测不宣称通过；若发现可复现的失联问题，在当前依赖的最小可行层修复并加测试，不预建通用恢复框架。
- 退出不无限等待在途系统调用；不增加指标落盘、持续诊断日志或外部遥测。

## 安装、路径与卸载

- 使用当前用户安装模式；启用时登记当前 Release EXE 路径，手动点击启用可以更新程序移动后的登记。
- 同一路径升级应保留已注册项及登录参数，不自动开启原先关闭的启动项。移动 EXE、删除便携程序或自定义不同路径安装不保证自动修复；在说明中告知重新启用。
- NSIS 卸载清理由本产品创建且指向本次安装 EXE 的启动项；不删除其他路径副本或无关项。插件注册名称／参数／引号规则与卸载钩子必须核对一致。
- 覆盖升级内部调用旧卸载程序时须保留本安装的启动状态，不能升级后悄然关闭或重新开启；以实际 NSIS 升级流程决定最少的钩子实现。
- 验证使用隔离安装目录，修改前记录已有启动项，仅操作测试拥有的项，结束恢复原状态；不覆盖用户已有安装。

## 验收与证据

1. 配置：v0.2 合法配置迁移保留全部原字段；损坏、未知版本、写入失败、显式保存行为均有测试。
2. 启动：手动可见、登录隐藏、登录可见、托盘失败可见、重复启动恢复、退出无自启均验证；登录标记测试与真实登录测试分别记录。
3. 注册：启用／关闭／查询／错误状态回归测试，实机核对注册路径、固定参数、操作后真实状态；关闭重开仍正确显示。
4. 生命周期：连续隐藏／恢复不产生重复 worker 或轮询；实际托盘菜单、休眠唤醒、接口变化及 Explorer 场景分别记录通过或未验证。涉及注销、重启系统或影响其他应用的 Explorer 重启，先获得用户针对该动作的许可，不用模拟状态替代实测。
5. 资源：最终 Release 显示及隐藏各至少 1 小时，预热后分别记录主进程及含 WebView2 的进程族 CPU、私有内存范围和趋势；不以一次测试宣称无泄漏或保证其他设备开销。开发观测文件与产品分离。未获得实机条件的检查如实列出。
6. 发布：TypeScript、前后端测试、fmt、Clippy、生产构建、Windows Release／NSIS；v0.2 同路径升级保留配置与启动状态，关闭状态不被开启；卸载仅移除自己的启动项。
