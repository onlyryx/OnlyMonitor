# Only Monitor v0.2 Resident Experience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 交付可通过托盘日常常驻、隐藏后持续采集、设置可保存且具有真实历史趋势的 Only Monitor v0.2.0 Alpha。

**Architecture:** 单个 Rust worker 独占 Collector，将最新状态与有界历史发布到共享缓存；前端只在可见时串行读取缓存。Rust 负责固定路径配置读写、托盘和单实例生命周期，沿用当前 sysinfo 采集与 ts-rs 类型生成。

**Tech Stack:** 现有 Tauri 2、React、TypeScript、Vite、Tailwind CSS、Recharts、Framer Motion、sysinfo、serde、ts-rs；增加 serde_json 和官方 single-instance 插件，启用 Tauri tray-icon。

**Spec:** `docs/superpowers/specs/2026-10-22-v0.2-resident-experience-design.md`（用户于本轮确认继续）。

## Global Constraints

- 目标 Windows，版本 `0.2.0`，展示 `v0.2.0 Alpha`；不主动升级现有依赖。
- 默认间隔 1 秒，支持 1／2／5 秒；上一轮完成后等待指定间隔，不重叠、不排队补采。
- 磁盘继续每 30 秒刷新；最近 60 秒内最多 60 条采样结果，不将指标或历史写入磁盘。
- 建议默认关闭窗口隐藏到托盘，已随设计确认；可改为退出。托盘退出始终真正退出。
- 只持久化 schemaVersion、samplingIntervalSecs、closeBehavior、selectedNetworkInterface，schemaVersion 固定 1。
- 继续普通用户权限运行，不上传监控数据、不运行 Shell、不发起 AI 请求、不部署网站或修改 DNS。
- 不增加温度、GPU、Ping、磁盘健康、开机启动、主题系统或自动更新。
- 当前不是 Git 仓库：先保存文件级可恢复基线，不虚构 commit、分支或 worktree；执行期间用记录文件跟踪任务与验证。

## Review Focus

1. 修改间隔或前端重挂载后生成第二个采集循环：任务 3 验证重复读取、连续修改间隔与 shutdown 后无后续调用。
2. 托盘不可用却吞掉关闭事件，使窗口无法恢复：任务 4 验证关闭决策函数的 trayReady=false 分支。
3. 配置保存失败但 UI 显示已保存／运行值已经改变：任务 2 验证写入失败，任务 5 验证拒绝保存后的 UI。
4. 隐藏期间发生接口消失或休眠，恢复时显示跨间隔伪速率：任务 3 验证基线重置，任务 5 验证历史空值与接口缺失。
5. 5 秒采样每轮都被固定 3.5 秒阈值标为过期：任务 5 验证 5 秒间隔下 10 秒未过期、超过 15 秒才过期。

**Interfaces:**

### Task 3: 唯一后台 worker、缓存与历史

**Files:** 新建 `src-tauri/src/runtime.rs`；修改 `collector.rs`、`model.rs`、`lib.rs`、生成的 `src/bindings.ts`。

**Interfaces:**

- `HistoryEntry { sampled_at_ms: u64, interval_secs: u64, snapshot: Option<Snapshot> }`；失败条目使用真实尝试时间和空 snapshot。
- `MonitorState { latest: Option<Snapshot>, history: Vec<HistoryEntry>, last_error: Option<String>, last_attempt_at_ms: Option<u64>, settings: Settings, config_error: Option<String>, tray_error: Option<String>, window_visible: bool }`。
- `MonitorService::start(settings: Settings, sampler: impl FnMut(u64) -> Result<Snapshot, String> + Send + 'static) -> Self`：每轮把有效采样间隔秒数传给 sampler；生产闭包捕获唯一 Collector 并调用 `Collector::sample(interval_secs)`，测试使用可控采样闭包，不新增通用 provider 框架。
- `MonitorService::read() -> Result<MonitorState, String>`；`apply_settings(settings: Settings)`；`shutdown()` 唤醒等待并停止后续调用，不在退出事件中无限 join 系统调用。
- `get_monitor_state` command 只返回缓存。阶段内可暂时保留旧 get_snapshot 为只读兼容层，任务 5 切换前端后移除它。
- 配置保存 command `save_settings(settings: Settings) -> Result<Settings, String>`：串行执行固定路径写入；成功后才 apply_settings 并清除配置错误。

- [x] 先写历史与状态测试：超过 60 条和超过 60 秒均剔除；失败追加空指标但保留 latest；恢复清除采集错误而不清除配置／托盘错误；重复读取不调用 sampler。
- [x] 写调度测试：慢 sampler 最大并发为 1；apply_settings 调整同一个 worker；shutdown 唤醒等待且不再采样。使用计数器／同步通道观察真实调用，不在产品代码中加入测试计数器。
- [x] 运行新测试观察失败，再用标准库线程和可唤醒等待实现单 worker。慢系统查询在状态锁外执行；前端读取只短暂克隆缓存。
