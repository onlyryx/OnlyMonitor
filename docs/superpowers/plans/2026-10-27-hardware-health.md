# v0.7 硬件温度与磁盘状态实施计划

> 在现有本地采样基础上分步实施；每项都保留不可用状态并单独验证。

**目标：**在普通用户权限下显示可读取的显卡温度和 Windows 报告的物理磁盘状态，让用户了解数据的来源与局限。

**架构：**通过独立的 Tauri command（相关页面可见时低频刷新，也可手动读取），在阻塞任务中读取驱动接口或 Windows 存储提供程序；不进入现有每秒采样循环，不执行 Shell。各读取使用独立的并发保护和时间戳。CPU 温度无法可靠取得时明确显示不可用，不将系统热区冒充 CPU 温度。

**技术：**Rust、Tauri 2、NVIDIA NVML 动态库、Windows WMI、React 与 TypeScript。仅读取本机数据；不请求管理员权限，不上传、不持久化监控结果。

1. 核实 NVML 与 Windows 物理磁盘状态在当前普通用户下的可用性；分别记录驱动缺失、权限拒绝与设备不支持的行为。
2. 建立类型化、有限并发的 GPU 温度读取；测试无驱动、部分设备失败、温度无效和成功结果。动态库只从系统目录读取。
3. 读取物理磁盘名称与 Windows 健康状态；测试正常、警告、异常、未知以及查询失败。明确说明该状态不是完整的 S.M.A.R.T. 诊断，避免推测卷与物理盘的对应关系。
4. 重整硬件与存储页面的层次，突出读数、更新时间、来源与下一步，保持窄窗口和中文阅读清晰；失败后清除旧结果。
5. 更新说明及验证记录，运行 Rust 与前端测试、类型检查、Clippy、构建，并在原生窗口核对可用与不可用状态。
