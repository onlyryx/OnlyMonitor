# 本次运行负载回看实施计划

**目标：** 让用户查看本次运行中持续高负载的时间和当时的少量占用线索。

**架构：** 在唯一 Rust 采样 worker 内维护 CPU／内存独立状态机；事件放入现有只读状态并使用独立命令清空。前端在 Activity 展示事件，使用现有类型生成与界面组件。

**约束：** 最近 20 条，每条最多 3 个进程；不落盘、上传或记日志；不新增采样循环；通知开关和事件检测互不控制；无管理员权限和外部请求。设计依据：`docs/v0.6-plan.md`。

## 实施步骤

1. 在 `src-tauri/src/events.rs` 实现独立的有界状态机，在 `model.rs` 添加事件 DTO。测试 30 秒触发、80% 以下 60 秒恢复、两指标独立、失败／长间隔中断、峰值、进程上限、清空后不重复及 20 条上限。
2. 在 `runtime.rs` 用同次采集结果更新事件，在 `lib.rs` 暴露清空命令并生成 `src/bindings.ts`。检查错误采样、时钟跳变及清空与采样的同步关系；通知逻辑保持独立。
3. 在 Activity 增加事件列表、时间、状态、峰值和触发时线索；增加清空反馈与空状态，修正隐私说明。检查窄屏布局、键盘按钮及未就绪／失败状态。
4. 更新 README、更新记录、版本与验收记录。运行针对性 Rust／前端测试、类型检查和构建；可行时使用 Windows 原生构建验证，无法验证的项目如实记录。
