# Only Monitor v0.4 计划：产品视觉与日常体验

更新：2026-10-26。状态：**M1–M4 已实现，自动检查及 Release 构建通过；原生尺寸／页面矩阵和长期常驻性能验收尚未完成**。上一已发布版本为 0.3.1 Alpha，当前源码标记为 0.4.0 Alpha。

执行依据：[工作纲领](WORKING-CHARTER.md)、[长期路线图](ROADMAP.md)。原 Plan A 保留为[历史评估计划](v0.4-baseline-plan.md)，[前置评估记录](v0.4-verification.md)基于 0.3.1；本版检查见[0.4 验收记录](v0.4-release-verification.md)。

## 1. 版本目标与已知事实

本版要交付一套用户愿意日常使用的新界面：**鲜明、有个性，带一点玩心，同时清爽、精致**；切换页面、修改设置和查看网络指标也应自然、可理解。

已确认的用户要求：
- 日常体验优先，文字必须清晰。
- 用户不满意旧版过于严肃、保守的风格，颜色也需要重新设计。
- 个人深色与紫色审美不应自动成为产品审美；此前的深色紫色要求已由最新反馈替代。
- 新气质结合“鲜明、有个性”和“清爽、精致”。用户已确认 B 的浅石色、森林墨绿与柠檬黄，并确认圆角玻璃和轻量页面切换修订版。

代码与观察提供的切入点：
- `src/App.tsx` 切页目前只修改 page，没有统一处理页面滚动位置；此前原生观察出现新页面承接旧页面底部位置的情况。
- SettingsPanel 的草稿保存在组件内，离开设置页时组件卸载，草稿没有跨页面保留机制。
- Overview 网络卡片使用全接口快照；Network 使用所选接口，概览与已保存偏好存在口径差异。
- 0.3.1 在本机 100% 缩放已获得阅读清晰度认可，但这不代表旧整体风格获认可，也不代表其他缩放已验证。

## 2. 范围与排除项

必做：视觉方向对照及选定、四个页面的视觉重设计、导航与滚动行为、设置草稿与保存反馈、网络统计口径统一、原生体验和相关常驻回归。

本版延后：GPU／温度、进程列表、磁盘 I/O、Ping、AI、长期历史、告警、浮窗、窗口位置持久化、双主题切换、自动更新、官网部署。新增页面内容不以这些能力作为前提。

保留既有技术栈、真实采集、单后台 worker、60 秒／最多 60 条历史和本地隐私边界。以已有配置字段完成本版交互；实现若确需配置升级，单独补充迁移与回退方案。

## 4. 任务定义与验收

### V1：视觉系统与阅读

最终视觉方向：用户确认 [B 圆角玻璃修订版](design/v0.4-candidates/index.html)。应用采用浅石色背景、森林墨绿文字和控件、柠檬黄重点色；卡片与侧栏使用半透明表面和柔和模糊，文字仍保持实色高对比。页面以 Framer Motion 短暂淡入／轻移，跟随系统减少动态效果设置。正式 UI 已落地，四页正常态已在原生窗口检查；完整阅读与响应式验收仍待用户在最终尺寸下确认。

设计输出：主背景／表面／文字／强调／状态颜色，字体与数字样式，间距与控件尺寸，图表线条和图例，聚焦、悬停、禁用、加载、空状态、错误状态。只为实际组件建立样式变量，不先建主题框架。

验收：
- 用户能明确选择符合“鲜明、有个性 + 清爽、精致”的候选，并在最终原生窗口确认方向落实。
- 大数字、标题和中文说明保持清晰；辅助字不小于 12 CSS px，常读说明目标 13–14 px。正文与背景对比度目标至少 4.5:1；文字不压在复杂渐变或模糊底层上。
- 个性主要来自配色、构图、排版和细节；CPU／内存／网络的主要读数在总览上部可辨认，界面不被装饰或 Coming Soon 卡片占满。
- 上下行线条有文字图例，错误与不可用有文字说明，不能只靠颜色辨别。品牌强调色与警告色的用途不混淆。
- 页面切换不会让主要文字明显长时间发淡或移动；遵循系统减少动态效果偏好。
- 真实指标只来自后端；设计原型中的固定数据明确标为演示，不进入正式采集路径。
- 主界面减少重复隐私宣传和未来能力占位，必要说明在 Settings／帮助位置仍可找到。安全与隐私行为本身不因此削弱。

### V2：导航、滚动与键盘操作

行为方案：跨页面导航进入目标页顶部；点击当前页导航时不强制改变滚动位置；隐藏再恢复保留当前页和滚动位置。手动重启默认进入 Overview，本版不增加跨重启页面记忆。

验收：
- 从 Network 或 Storage 底部切换到其他页，看到目标页标题和首要信息，而不是旧滚动位置。
- 侧栏与“查看接口明细／查看全部磁盘”使用一致的导航行为。
- 键盘可依次到达导航、选择框与按钮；聚焦位置可见。键盘跨页后焦点落在目标页明确位置，采样刷新不抢焦点。
- 鼠标滚动查看详情时不会被每秒刷新拉回顶部；同页点击、隐藏恢复均符合上述规则。
- 四页面在 760×600、900×700、1320×900 的逻辑内容尺寸下没有页面横向溢出；垂直滚动允许，关键控件可访问。

### V3：设置草稿、保存与反馈

行为方案：在本次应用会话中保留设置草稿，切页或隐藏恢复不丢失；不把未保存草稿写入磁盘。增加“有未保存更改”和“恢复当前生效设置”，无需为普通切页反复弹确认框。真正退出后未保存草稿不保留，界面在有草稿时说明这一点。

验收：
- 修改采样间隔或关闭行为，离开 Settings 再回来，草稿仍在，当前生效值与草稿可区分。
- 无修改时保存按钮不造成无意义写入；保存中不能重复提交。
- 保存成功才更新生效值并清除未保存状态；保存失败保留草稿和原有效配置，给出明确失败原因与重试入口。
- “恢复当前生效设置”只撤销未保存编辑，不等于恢复出厂默认值。
- 登录启动操作仍独立立即生效，不提交其他草稿；慢操作、失败和结束后轮询恢复都保留现有保障。
- 网络页保存接口偏好时，不能让 Settings 的草稿丢失，也不能让随后保存旧草稿覆盖刚保存的接口。提交时仅应用本表单负责的字段到最新有效设置。
- 后台状态刷新不重置用户正在编辑的字段，不抢焦点。

### V4：网络数据口径

行为方案：Overview 使用**已保存**的监控接口偏好；Network 选择未保存的接口可以立即预览，并标明“预览，尚未保存”。保存成功后两个页面采用同一统计范围。

验收：
- 保存接口 A 后，总览和详情明确标注接口 A；对同一后端快照计算出的上下行值相同，不要求不同采样时刻的截图数值相等。
- 预览接口 B 未保存时，不把它伪装为已生效全局偏好；切页返回后保留本次会话的预览选择并显示未保存状态，退出后仍使用已保存值。
- “所有接口”继续保留，并明确可能重复计数；不将其命名为“互联网实际网速”。
- 所选接口消失时保留选择，显示不可用／等待重新出现，不静默切换到全部接口，不把缺失值显示为 0。
- 首次、接口新增、计数回退、采样中断沿用真实初始化与断线逻辑。
- 保存失败保持原有效接口，并保留可重试的预览选择。

### V5：原生验收与常驻回归

自动检查按改动执行：TypeScript、前端测试与生产构建；新增交互测试覆盖草稿保留、保存失败、跨表单字段保护、导航行为及接口口径。Rust 逻辑若有修改，增加对应 Rust 测试、类型契约、格式与 Clippy 检查。最终必须生成并运行 Tauri Release。

原生检查：
- 四页面的正常、初始化、不可用、失败与过期状态；不能通过伪造生产数据来模拟成功。
- 100% 缩放及前述三组窗口尺寸必须实测；125%／150% 尽可能在真实 Windows 缩放环境验证。浏览器缩放或设备模拟不能代替原生 DPI 验证；无法实测则列出限制，不宣称多 DPI 已通过。
- 从托盘恢复、关闭隐藏、最小化恢复、第二实例恢复、真正退出；确认进程没有重复常驻，恢复后数据更新且错误状态可信。
- 用短时只读诊断检查实际历史条数与时间跨度；隐藏／最小化期间 UI 读取次数和时钟暂停单独观察，不能仅凭恢复后的新时间宣称通过。
- 用户分别验收整体风格与文字清晰度；“能读清”不能替代“愿意使用这个设计”。

性能检查：
- 新旧 Release 在同机同尺寸、同缩放、同采样间隔下比较。每个状态预热后测量：Overview、Settings 各 5 分钟，交替两轮；隐藏与最小化各 5 分钟。保存原始样本、进程变动和测量条件。
- 不同时进行编译或持续 DevTools 调试。首次 CPU 速率为空，跨进程重启的样本单独标识；不把瞬时峰值或单次中位数当作结论。
- 出现两轮一致的额外开销或持续增长时定位原因；未解释的明显回归不通过。没有证据时不为优化而重构。
- 若修改采集调度或窗口生命周期，追加可见／隐藏各 60 分钟检查；纯视觉改动不自动重复全部长测。
- 真实睡眠／唤醒、Explorer 重启和物理断网会影响当前会话，安排独立验证窗口；未经实际执行不得写成已通过。
