## 原生预览与范围

- 使用独立应用标识 `com.onlyryx.monitor.v06preview` 运行 Windows 开发版；Overview 显示真实采样，Activity 显示真实当前进程排行和事件空状态。事件卡片调整到 Activity 首屏后在窗口中观察到其位置与隐私说明。
- 2026-10-27 以独立身份再次启动开发版，将窗口隐藏后进行约 48 秒、8 线程受控 CPU 负载；Windows 计数器抽样显示 100%。恢复同一进程窗口后出现 CPU 高负载事件，开始时间 10:17:24、确认时间 10:17:55，表明事件在窗口隐藏期间产生。
- 展开事件详情后，原生窗口显示真实开始和确认时间、100.0% 峰值和最多 3 条确认时的进程占用线索；停止负载后，事件于低负载恢复观察后显示“已恢复”，最近有效采样为 10:19:13。
- 已恢复事件通过界面“清空事件”清除，页面回到空状态且采样继续。第二轮约 48 秒负载期间，在事件仍显示“进行中”时清空；界面保持空状态直至负载结束，未立即重新生成同一事件。两轮负载进程均已自动结束。
- 使用 Windows 窗口菜单将预览缩至约 770 × 900 像素：空状态、实际事件摘要和展开详情均可显示，进程线索可换行，进程排行保持可读；本次未覆盖其他 DPI 或最小窗口尺寸。
- 补充中断实测：在独立标识开发版中先用约 43 秒受控 CPU 负载生成真实事件，再仅暂停该预览进程 13 秒并恢复。事件由“进行中”变为“采样中断”，详情保留中断前最后有效采样时间 10:30:29 和已观察 51 秒；恢复后页面重新显示实时采集。此项模拟进程暂停，并非 Windows 实际睡眠或采集 API 报错；安装版进程没有被暂停。
- 补充尺寸和缩放实测：在 Windows 100% 缩放下将独立预览窗口缩至接近应用最小尺寸（配置为 450 × 600），展开的事件详情可换行，纵向滚动可到达清空按钮和排行。临时将 Windows 显示缩放从 100% 调整到 125%，用户直接观察后确认标题和中文说明“清晰可读”；完成后已恢复原来的 100%，分辨率保持 1920 × 1080。125% 下自动化截图的小字出现失真，Windows 设置界面也有类似现象，因此文字清晰度以用户直接观察为证据；未完成 125% 最小尺寸或其他 DPI 的目视验收。
- 睡眠恢复尝试：Windows 睡眠 API 返回成功，但调用前后系统日志的最新事件编号没有变化；日志中较新的睡眠／唤醒记录时间早于本次尝试，不能作为本轮进入睡眠的证据。Only Monitor 窗口仍正常采样，但这只证明应用保持运行，不能证明经历了真实睡眠。
- 采集失败通路检查：当前真实运行数据正常，未对系统设备或服务制造故障。源码检查确认采样错误会保留最后成功快照、标记采集失败并在成功采样后清除错误；运行时失败分支已有单元测试覆盖。尚未在原生窗口注入一次真实采集失败。
- 中断测试的受控 CPU 负载也被正常运行中的安装版记录为一次事件。核对该事件与测试时间一致、当时列表中仅有该测试事件后已清空；安装版仍在运行，采样间隔及通知关闭设置不变。
- 开发版首次加载曾显示空白，随后完成加载；本次没有测量启动耗时，也没有因此认定存在或不存在启动性能问题。
- 提醒设置在已安装 v0.5 的配置中仍为关闭；预览使用独立身份，没有覆盖其配置。预览结束后进程已停止。
- 事件仅在 `MonitorState` 的内存状态中维护；清空命令只移除内存事件，设置文件不包含事件或进程数据。此结论来自实现检查，未进行文件系统或网络流量专项监测。

## 安装版原生验收

- 经用户确认，在安装器中选择不卸载旧版，将 v0.6 安装至 `.tools/v06-native-check` 并启动。当前用户的 Windows 安装登记显示 0.6.0 并指向该目录；v0.5 可执行文件仍保留在 `.tools/v05-native-check`。两个版本共用产品安装登记，不能将旧文件仍存在视为两份独立安装登记。
- 安装版 Overview 显示真实采样，Activity 正常显示。已有设置仍为 1 秒采样、关闭窗口隐藏到托盘、高负载通知关闭。
- 将安装版窗口隐藏后进行约 45 秒、8 线程受控 CPU 负载，再通过再次启动恢复原进程窗口。后台产生 CPU 高负载事件，开始于 10:24:56，确认于 10:25:27；详情显示 100.0% 峰值及当时最多 3 条进程线索。
- 负载结束并经过恢复观察后，事件显示“已恢复”；点击“清空事件”后回到空状态，系统采样继续。受控负载已结束，安装版保持运行。
