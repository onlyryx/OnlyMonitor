# Only Monitor v0.6 计划候选：本次运行的负载回看

日期：2026-10-27。状态：**方向已确认，正在实施**。起点为 v0.5.0 Alpha；既有事实和未验证项以 [v0.5 验收](v0.5-verification.md)为准。

## 目标与现状

用户离开电脑一会儿后回来，希望知道“刚才为什么变慢”，而不只是看到现在的排行榜。v0.5 已能展示当前进程 CPU／驻留内存、托盘摘要和可选通知；系统历史最多保留约 60 秒，进程排行只保留当前快照，退出后清空。现有数据不足以回看稍早前的进程，不能声称已有事件记录或根因分析。

建议 v0.6 增加**本次运行内的持续高负载事件回看**：记录有限数量的 CPU／内存高负载片段，并保留触发时的少量进程线索，让用户了解何时发生、持续多久、负载有多高及当时哪些进程占用较多。记录只在内存中，退出即清空；进程排行是相关线索，不能宣称造成了高负载。

## 方案比较

| 方案 | 收益 | 代价与边界 |
| --- | --- | --- |
| 只完善 v0.5 当前排行榜 | 改动小、无额外事件数据 | 用户回来后仍无法看到此前的持续高负载 |
| **建议：有上限的内存事件回看** | 解释近期异常，复用已有采样，退出即清空 | 只能覆盖本次运行和有限事件；需要明确缺失、终止与采样口径 |
| 持久化完整历史或接入 AI 分析 | 可跨重启回看、提供更丰富分析 | 引入隐私、存储、性能或模型依赖，超出当前本地内存边界，需独立决定 |

用户已确认内存事件回看方向。暂不扩展为进程管理、全量进程历史、磁盘 I/O、传感器或自动诊断。

## 实施范围与语义

1. **事件形成**：独立于通知开关，建议沿用现有高负载口径：CPU 或内存达到 90% 持续 30 秒才形成对应事件；确认前任一样本低于 90% 则重新计时；低于 80% 持续 60 秒视为该指标恢复，恢复期间回到 80% 或以上则重新计时。通知仍按既有设置独立控制；开启记录不自动开启通知。
2. **可解释记录**：展示指标、首次达到阈值的采样时间、确认时间、持续时间、事件期间观察到的峰值，以及确认触发时对应资源排行中最多 3 个进程的名称和数值。进程数据只代表触发时的快照；不可用或未建立 CPU 基线时明确显示未知。
3. **中断与时间**：失败、缺失、休眠或过长采样间隔不补算连续时长，不连接成看似完整的事件；进行中的事件在中断时标记为中断，结束时间使用最后有效采样。持续时间以单调时钟计算，展示时间使用采样时间；时钟异常不拼接不同时间线。
4. **内存上限**：建议最多保存本次运行最近 20 条事件，每条最多 3 条进程线索；超出时优先丢弃最旧的已结束事件，进行中事件计入上限。清空入口清除列表，同时丢弃进行中事件的展示记录；检测状态继续运行，直到该轮恢复后才可记录下一轮，避免清空后立即重复生成。清空不改变采样或通知设置；退出即清空，首版不落盘、不上传或写入日志。
5. **界面**：在现有 Activity 中增加紧凑的近期事件区及空状态；事件区解释“进程为当时占用线索”。沿用已确认的圆角、玻璃视觉和清晰字体，窄窗口保持可读，尊重减少动态效果设置。

CPU 与内存独立计时；进程驻留内存包含共享部分，受保护进程可能不可见。事件开始时间是观察到满足条件的时间，不等于系统真实异常开始的精确时刻。持续时间包含恢复确认所需的低负载观察时间，直到事件恢复或中断的最后有效样本为止。

## 实施顺序与验收

| 顺序 | 工作 | 可观察的验收标准 |
| --- | --- | --- |
| 1 | 核对 v0.5 未完成项及事件数据边界 | 沿用 [v0.5 验收](v0.5-verification.md) 的真实状态；确认通知投递、横幅外观和托盘交互的证据分别记录 |
| 2 | 实现有界事件状态，接入现有唯一采样器 | 两个指标独立形成与恢复；短暂高负载不生成事件；缺失或长间隔中断事件；最多 20 条，退出不写文件；通知关闭时仍可形成事件 |
| 3 | 采集触发时的有限进程线索并生成类型 | 仅使用同次有效快照；最多 3 条；进程缺失或 CPU 基线未建立显示未知；不保存完整进程表，也不伪造因果关系 |
| 4 | 在 Activity 提供事件列表、详情和清空 | 可区分进行中、已恢复、中断；时间与数值有单位；空状态、数据不可用、窄窗口及键盘操作可用；清空后监控继续 |
| 5 | 验证与交付 | 与改动相关的逻辑、类型及构建检查通过；在 Windows 安装版验证可见与隐藏时行为、负载触发、恢复和中断；记录环境、结果和未验证项；版本号与安装包一致 |

实现前应核对现有通知状态机能否共享规则而不改变通知开启／关闭语义；若共享会造成事件与通知互相重置，就保持各自状态并复用明确的阈值定义。使用现有依赖和 Rust/TypeScript 分层，不新增采样线程、管理员权限、任意 Shell、外部请求或后台持久化。

## 保留到独立决策

跨重启保存、数据导出、阈值自定义、AI、硬件传感器、主动网络请求和自动更新均不属于本建议。签名发布需要相应证书与发布流程；无法验证的环境或人工交互应继续如实记录。
