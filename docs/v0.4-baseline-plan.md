# 历史计划：v0.4 前置常驻与资源评估

归档日期：2026-10-26。以下保留原 Plan A 的范围与当时记录，评估对象为 0.3.1，不代表已交付 0.4.0。当前方向以[重新制定的 v0.4 计划](v0.4-plan.md)为准；旧视觉约束已被用户最新反馈替代。

## 目标

优先级调整（用户反馈）：文字阅读修复已作为 v0.3.1 Alpha 完成，用户在原生对照和真实修复版窗口中均确认改善。结果见 [v0.3.1 验证记录](v0.3.1-verification.md)。v0.4 常驻与资源基线已于 2026-10-26 完成，未发现足以支持产品代码修改的可复现问题。

在 v0.3 单 Rust 采集器、隐藏时停止前端轮询的基础上，检查图表与 WebView2 的实际资源开销，并验证日常隐藏、最小化和恢复流程。只有可复现的测量或行为问题才触发产品代码修改。

### 文字清晰度调查

- 运行中的 Release 窗口实测为 96 DPI，DPI awareness 为 per-monitor；未发现本 EXE 的 Windows DPI 兼容性覆盖，系统字体平滑已开启。
- 本应用 WebView2 配置中未发现保存的页面缩放覆盖；代码没有自定义 zoom／scale。此项不等于已经测到 WebView2 内部实际栅格化比例。
- 页面大标题位于内容动画容器外，不能将大标题发虚直接归因于该动画。卡片具有 backdrop-filter，字体包含大量 8–11 px 文本，具体影响仍需对照。
- 原生对照确认像素比／视口缩放为 1，英文标题在两种字体族下实际都为 Segoe UI Semibold。采用用户确认的阅读候选，修改数字字重、字距、辅助字号及对比度和卡片文字背景；真实新版经 12 组原生窗口布局检查及用户验收通过。未声称证明某个底层 WebView2 缺陷。

## 范围

- 比较同一 Release 进程在 Overview（显示趋势图）和 Settings（不显示趋势图）时的主进程、WebView2 子进程私有内存及 CPU。
- 验证从隐藏／最小化和第二实例启动后恢复窗口，且采样继续推进、历史仍有界。
- 检查窗口隐藏与最小化期间前端轮询和时钟是否停止；区分 Windows 最小化与应用隐藏行为。
- 若测量找到可重复的开销或缺陷，先写回归，再做最小修正，并比较同机同条件结果。

## 实施计划

1. 用逐次重新枚举子进程的只读采样器建立同进程页面基线，避免子进程退出／重启污染总量；不使用持续 DevTools 连接或强制垃圾回收。
2. 在原生窗口中切换 Overview 与 Settings，记录每种状态的样本数、持续时间、进程族构成、CPU 与私有内存范围；短测差异不单独作为优化依据。
3. 通过现有单实例入口恢复原窗口，检查真实采样时间、历史长度与可见状态；复核前端可见性监听及已有轮询回归测试。
4. 若发现可复现问题，补充测试并实施最小改动；若没有，保留代码不动并记录基线与验证边界。
5. 对产品改动运行相关测试、类型检查、构建和 Release 行为验证；更新本计划及验证记录。

## 验收标准

- 资源记录明确标出 UI 页面、进程 ID 与时间；测量前后进程族均重新枚举，短时子进程变化不被误报为图表内存差异。
- 恢复后同一应用进程仍在运行，采样时间推进，最近历史不超过 60 点。
- 如改代码，问题有可重复测试且修复后通过；没有证据时不为推测增加复杂性。

真实休眠／唤醒、Explorer 重启和物理网卡断开会影响当前 Windows 会话，列为单独的系统级验证，不包含在本轮无中断检查中。

## 本轮结果

详见 [v0.4 验证记录](v0.4-verification.md)。当前结果属于短时同机基线；图表页 CPU 差异尚未达到改代码门槛，私有内存受切页后的 WebView 回收影响，不作固定页面成本解释。单实例恢复与采样时间推进通过，现有前端可见性、无重叠刷新和 Rust 有界历史测试通过。未修改产品代码或用户配置。
