## 资源观察方法修正

2026-10-24 的前期长测使用持续的 Playwright CDP 连接，观察到渲染进程原生缓冲增长，而 JS 堆没有对应增长。断开该连接后，渲染进程私有内存由约 339.73 MiB 降至约 132.91 MiB。这一现象与调试连接保留 IPC 响应相符，不能把前期增长直接归为产品泄漏。

前期记录与正式资源摘要分开保存，本机逐条记录未纳入公开仓库。分析期间仅请求非确定性内存快照，未主动强制垃圾回收。用户按 Esc 后停止了该轮工作；中断后的无人观察时间不算完成的测试。

2026-10-26 正式观察重新启动最终 Release：每 10 秒读取主进程与 WebView2 子进程的资源计数，每约 55 秒通过短连接 Runtime 探针核对采样推进、可见性及历史边界，不启用持续 Network 调试域。记录窗口可被其他桌面应用遮挡；这是实际桌面常驻观察，不是持续前台渲染基准。CPU 按 8 个逻辑处理器归一化；内存为私有提交字节；每阶段前 60 秒预热不计入摘要范围。

## 依赖取舍

核对官方 autostart 2.7.0 与 2.5.1 的 Windows 后端后发现会更改 StartupApproved，且未给 EXE 路径加引号。最终保留官方 2.5.1 API，通过 Cargo patch 使用 auto-launch 0.5.0 的本地 MIT 源码，仅改 Windows 后端：固定参数路径引用、只写 HKCU Run、不修改系统批准状态、严格查询错误、拒绝关闭其他路径的登记。

此选择增加本地依赖补丁的维护成本；详见 [PATCH.md](../src-tauri/vendor/auto-launch/PATCH.md)。插件查询只报告当前路径启动项登记，不保证 Windows 策略允许实际登录启动。

本轮其他工程取舍及代价：

- 没有 Git 时使用源码／产物文件基线和手动执行记录，不能按提交回滚；按用户要求计划后连续实施，没有再添加一轮计划审批。
- Vitest 仅发现 src 内测试，防止临时解压的旧版测试混入计数；未来放在其他目录的测试需显式纳入。
- 保留原采集、历史及关闭架构，不扩展跨平台和签名；sysinfo 的网络错误诊断与同步磁盘发布时间限制仍在。
- 系统注册为启动状态真源；显式启用可更新同名登记路径，关闭拒绝删除其他路径，只编码固定参数。Windows 策略仍可能阻止已登记项执行，任意参数需另行处理。
- 保留现有单实例与窗口聚焦实现，不增加未经实际失败支持的恢复框架；极端聚焦／初始化错误和外部同时编辑启动项的竞态仍未充分验证。
- 对真实登录、休眠、Explorer、托盘点击与受限账户等缺少实机证据的场景明确保留验证边界，不以只读审查或纯逻辑测试代替。
- 重新开始正式资源观察，以排除持续调试连接的缓冲保留；代价是额外观测时间，旧数据另存而不作为正式结果。

独立审查没有搁置的小问题；两项重要问题均已完成回归修正。
