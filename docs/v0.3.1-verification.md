# v0.3.1 Alpha · 字体阅读修复验证

日期：2026-10-26，Asia/Shanghai。

## 原生对照与结论

用户报告大标题、大号数字和中文说明的边缘发虚。运行中的旧版主窗口实测为 96 DPI、per-monitor awareness；系统字体平滑已开启，没有发现针对该 EXE 的兼容性 DPI 覆盖。

使用相同的 Tauri 2.12.5／WebView2 155、独立应用标识的原生对照窗口，在同一窗口比较原版样式和候选。对照窗口中 devicePixelRatio=1、visualViewport.scale=1、CSS zoom=1；英文标题实际均回退为 Segoe UI Semibold，因此只改字体族没有改变英文标题字形。不能据此把现象归为 HTML 或某个已确认的 WebView2 缩放故障。

候选将数字字重提高为 600、放松标题及数字字距，使用 Segoe UI／Microsoft YaHei UI 回退，放大并提高辅助文字对比度，取消文字卡片的 backdrop-filter。用户在真实屏幕确认“右侧明显更清楚”，据此将候选落实到产品；这是阅读表现的修复，不声称已证明某个底层渲染器缺陷。未修改 Windows 缩放、ClearType、GPU 开关或系统注册表设置。

证据：[原生对照图](v0.3.1/typography-native-comparison.png)、`v0.3.1/typography-initial.json`、`typography-readable.json`。对照工具位于 `.tools/typography-probe/`，没有加入产品。

- 旧版 EXE／安装包及本轮修改文件备份在 `.tools/baselines/v0.3.0/`。

## 验证结果

- TypeScript 类型检查、前端 4 文件／15 项测试、生产前端构建通过。
- Release／NSIS 构建通过；实际新版 WebView 的像素比与视口缩放均为 1，大标题 33 px／600 字重、大数字 50 px／600 字重，当前可见文字不低于 12 px。
- 通过原生窗口边框拖动到 1320、900、760 px，四个页面共 12 种组合均无页面、卡片及控件横向溢出。真实数据为 8 个逻辑核心、34,275,844,096 字节 RAM；历史不超过 60 点，采样正常，无采集或配置错误。本机逐条记录未纳入公开仓库。

- 用户在实际修复版窗口中再次确认“已经清楚、可以日常使用”。本轮实测为当前机器、100% 缩放；其他显示器及 125%／150% 缩放尚未实测。
- 对照进程、两个临时调试端口已关闭；以不带调试参数的普通方式重新启动 0.3.1，原配置与测试前备份逐字节一致。启动登记未作修改。
- 安装包已生成；本轮没有重复 v0.3 的完整安装升级矩阵或两阶段一小时常驻测试，未将这些旧结果写成本轮新增验证。
