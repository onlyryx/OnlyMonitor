# Only Monitor v0.4.0 Alpha · 验收记录

日期：2026-10-27。候选方向 B（浅石色、森林墨绿、柠檬黄、圆角玻璃与轻量切页）已由用户确认。本文记录本次实现检查；未列作通过的项目仍未验证。

## 已通过

- `npm test -- --run`：5 个测试文件、18 项通过，覆盖启动、采样状态、导航／焦点、设置草稿及网络接口选择行为。
- `npm run typecheck`：通过。
- `npm run build`：通过。Vite 提示 JavaScript 主包超过 500 kB；本轮没有因此改变依赖拆分。
- `npm run tauri -- build`：Windows x64 Release EXE 及 NSIS 安装包生成成功。
- 运行 Release 原生窗口（屏幕窗口约 1320×900）：Overview 显示更新中的真实 CPU、内存、网络及卷容量；v0.4 配色、图表和卡片可见。新增的磁盘／网络辅助文字已复核为较深颜色。
- 原生 Settings 页面已打开检查；稳定显示后设置文字和控件清晰。过渡动画期间截屏曾捕捉到中间帧，稳定帧正常。
- 未启用登录启动、未保存设置、未改变网络接口偏好。
- 自定义标题栏已在 Windows Release 原生窗口检查：系统标题栏替换为应用标题栏，最小化／最大化／还原控件可用；关闭窗口后进程仍在托盘运行，再次启动同一程序可恢复窗口。
- Win+Z 能打开 Windows Snap 布局面板；Win+左方向键可将窗口贴靠到左半屏，仪表盘随较窄宽度重新排版；Win+上方向键可恢复最大化。

## 尚未完成

- 四页面均已在 Release 原生窗口打开检查（屏幕约 1320×900）；Overview 的读数和曲线、Network 的接口速率与断线说明、Storage 的真实卷列表、Settings 的常驻选项均可见。该检查只覆盖正常运行态，未覆盖异常和初始化状态；页面切换时截到的淡入中间帧会在短暂过渡后恢复正常。
- 未实测 760×600 与 900×700 的原生窗口尺寸。尝试使用屏幕边缘拖动时命中页面滚动条／系统菜单，无法确认应用实际缩放；不把这一尝试算作通过。
- 未验证 125%／150% Windows DPI、键盘逐页操作、原生失败状态及真实窗口滚动位置。
- 未完成 Release 资源测量、隐藏／最小化的 5 分钟对照、托盘恢复／第二实例及睡眠唤醒检查。
- 尚未验证悬停自定义最大化按钮直接弹出 Snap 布局、鼠标拖动标题栏及窗口边缘缩放；键盘 Win+Z／方向键的通过结果不替代这三项检查。
- 本轮用桌面自动化尝试直接拖动标题栏和窗口边缘，但未能稳定确认窗口位置／尺寸变化；自动化接口也没有单独的鼠标悬停动作。因此这三项仍保持未验证，需在原生桌面上人工检查或使用可读出窗口几何信息的验证环境。
- 整体视觉方向已获用户选择，但尚未取得用户对最终 v0.4 原生窗口整体风格和日常阅读的验收。
